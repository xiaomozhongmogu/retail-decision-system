# 经营周报盲测方案（交给 GPT 执行）

- 版本 v1，2026-11-11，claude-opus-5-5 起草；对应任务 AI-10（周报场景验收）
- 定位：GPT 盲测属于**独立 AI 复核**。它可以发现我方校验器漏掉的问题，但**不等于人工抽查**；AI-10 要求的人工抽查仍需真人另做，记录中分开登记。
- 数据：完全合成的模拟电商数据（截止 2026-11-08），金额单位 USD。

## 1. 测什么

被测对象：系统自动生成的“经营周报”。生成方式如下：

- 程序从数仓计算出一份**事实表**（每个数字都有编号 evidence_id、单位和时间窗口）。
- LLM 只写解释、行动建议和“待验证”假设，数字由程序填入。
- 发布前，程序再做一次确定性校验。

盲测要回答三个问题：

1. 周报里的数字、单位、时间窗口和引用编号，是否都与事实表一致？
2. 是否有没有依据的因果结论，或者提到了数据里没有的字段（渠道、毛利、库存等）？
3. 我方校验器放行的报告里，是否还有它没发现的错误？

## 2. 材料包（由 claude-opus-5-5 生成，放在 `eval/blind_packet/`）

| 文件 | 内容 | 是否给 GPT |
|---|---|---|
| `facts_*.json` | 每个场景的事实表（唯一的数字依据） | 给 |
| `knowledge.md` | 口径规则摘录：有效购买、审批时间、商品金额不含运费、数据中没有的字段 | 给 |
| `reports/R01.md … R24.md` | 24 份周报，编号已打乱 | 给 |
| `answer_key.json` | 每份报告植入了哪些错误、场景类型、生成方式 | **不给**（只留给我方对照） |
| 我方校验器的结果 | 哪些被放行、哪些被拦截 | **不给** |

### 2.1 场景覆盖（AI-10 要求至少 20 个）

| 场景 | 说明 | 份数 |
|---|---|---:|
| 正常周 | 真实数据的最近完整周 | 4 |
| 环比下降（负净额） | 本周金额低于上周 | 3 |
| 分母为 0 | 上一期没有订单，环比应显示“—”或“无法计算”，不能写 0% 或无穷大 | 3 |
| 小样本 | 基期订单少于 30 单，增长率不应给出 | 3 |
| 不完整周期 | 含审批未落定的最后一天或不完整月，不能与完整期间直接比较 | 3 |
| 植入错误 | 在上面场景的合格报告里人为改错，用来测 GPT 能不能发现 | 8 |

### 2.2 植入错误的类型（只写在 answer_key 中）

1. 改动一个数字（例如 13,306.01 改成 13,360.01）
2. 单位错误（USD 写成“元”，或比例写成金额）
3. 时间窗口写错（报告周的日期错一天）
4. 引用了事实表中不存在的 evidence_id
5. 写了没有标“待验证”的因果结论（例如“金额上升是因为促销”）
6. 提到数据中没有的字段（渠道、毛利、库存）
7. 把不完整周期当作完整周期比较
8. 分母为 0 时写成“增长 0%”或“增长无穷大”

每份植入报告只改 1 至 2 处，并保留合格报告作为对照，用来测误报。

## 3. 交给 GPT 的指令（直接复制）

> 你是一名独立的数据报告审查员。附件里有若干份电商经营周报（R01–R24）、每个场景的事实表（facts_*.json）和口径规则摘录（knowledge.md）。数据是完全合成的模拟数据。
>
> 请逐份检查每份周报，**只以事实表和口径规则为依据**，不要用常识或外部知识补充事实。检查项：
>
> 1. 每个数字是否能在对应事实表中找到，数值和单位是否一致（允许千分位和保留两位小数的格式差异）；
> 2. 时间窗口和对比期间是否与事实表一致；
> 3. 引用的 evidence_id 是否存在于事实表中，且对应的就是它所说的指标；
> 4. 是否有没有标“待验证”的因果结论；
> 5. 是否提到数据中没有的字段（以 knowledge.md 为准）；
> 6. 分母为 0、小样本、不完整周期是否被正确处理（不给出不可信的增长率，不与完整期间直接比较）；
> 7. 解释的语义是否与数字矛盾（例如数字下降却写成增长）。
>
> 对每份报告输出一行 JSON，不要输出其他内容：
> `{"report": "R01", "publishable": true/false, "issues": [{"type": "数字|单位|窗口|引用|因果|不存在字段|特殊情况处理|语义", "quote": "报告原文片段", "evidence": "事实表中的依据或缺失说明", "severity": "高|中|低"}]}`
>
> 没有问题的报告输出 `"issues": []`。不确定时写入 issues，severity 写“低”，并在 evidence 中说明不确定的原因。

## 4. 评分方式（由 claude-opus-5-5 对照 answer_key 计算）

| 指标 | 计算 |
|---|---|
| 植入错误检出率 | GPT 指出的植入错误数 ÷ 植入错误总数（按类型分别统计） |
| 误报率 | 合格报告中被 GPT 判为“不可发布”的比例；逐条复核，区分真误报和我方漏标的真实问题 |
| 我方校验器对照 | 同一批报告中，我方确定性校验拦截了哪些、放行了哪些；GPT 发现而校验器放行的问题列为改进项 |
| 新发现 | 不在 answer_key 中、经复核属实的问题（说明生成或校验还有漏洞） |

结论只描述这 24 份报告上的结果，不写成“所有输入都不会出错”。

## 5. 交回与登记

1. 把 GPT 的完整输出（每行一个 JSON）原样保存为 `eval/blind_packet/gpt_review.jsonl`，并写明使用的 GPT 型号和日期。
2. claude-opus-5-5 计算第 4 节的指标，写入 `reports/ai/report_evaluation.json`。证据登记为：复核者 = GPT（型号）、方式 = 独立 AI 复核。
3. 人工抽查另行登记：真人从 24 份中任选至少 5 份，按第 3 节同样的检查项填写结果。未完成时，AI-10 保持“待验收”，并写明“人工抽查待完成”。
