## 先恢复实际上下文

1. 实际读取根目录 `AGENTS.md`；不要假定你的平台自动读取、能访问其他 AI 的记忆，或拥有尚未验证的工具能力。
2. 盘点现有文件与修改，读取 `project/tasks.json`、`project/requirements.json`、`PROJECT_SPEC.md`，以及当前任务涉及的 `contracts/` 文件。
3. 阅读 `ops/DECISIONS.md` 中相关有效决定、当前任务在 `worklogs/` 的交接和 `evidence/` 的相关结果。以更新的权威台账为准，旧交接只作历史参考。
4. 检查实际可用的文件读写、命令执行、浏览和数据/API 访问能力；检查 Git 基线和未提交修改。不要重建覆盖、清理未知修改或把目标 Mac/ARM64 环境当成当前实际执行环境。

当前状态只由真实文件恢复。治理包初次交付不意味着业务代码或数据已经准备好；初始数据尚未选定，数据时效口径尚未确认。若已有后续证据，应采用更新后的有效状态。

文件缺失或无法访问时如实说明，并请求完成当前任务所需的最小文件集合；能先做的审查或补丁继续做。不要声称已读取、已下载或已保存不可访问的内容。

## 立即选择并推进任务

默认串行接力，由本轮被指定的协调执行者更新唯一任务台账。先恢复当前合法认领的任务；没有活动任务时，选取依赖满足、在授权范围内的最小必做任务。**不要默认选择可选 `BON` 任务。**

开始前只需简短说明：本轮任务 ID 和结果目标、可修改范围、现有授权、验收条件，以及真正的阻塞。随后执行，不把启动检查变成长篇规划。

依赖是最终验收的前置条件。基于稳定契约可先做不受阻的离线实现或夹具测试，明确待集成、待真实调用；前置未完成不能提前done。

使用状态脚本前先确认其实际帮助或实现，不编造子命令。`TASKS.md`、`REQUIREMENTS.md`、`STATUS.md` 仅由 `scripts/project.py render` 生成，不手工维护另一份状态。

遇到字段、时间、标签或指标不一致时，先核对有效契约。修复实现偏差可直接继续；改变有效口径需记录差异、影响和授权依据。已有授权覆盖的选择不重复申请，确实需要新增决定时先完成不受影响的工作，再给出一个具体问题与推荐方案。

## 真实执行，明确证据

按任务验收标准保存实际文件、命令结果、日志、断言和必要截图，并登记到 `evidence/<task_id>/`。区分真实运行、静态检查、样本、模拟、回放和用户提供的结果。

不能运行时，交付标明未运行的补丁、已有静态核验与最小验收命令，保持待验证状态；不能标 `done`，不能虚构预期日志或分数。运行失败时保留真实失败，能修复就继续。阻塞只影响相关任务，其他可推进工作继续。

每项课程要求最终都应能关联到当前有效证据。未确认的教师口径、未取得的数据、未完成的验证和未发生的提交必须保持可见。

## 本轮结束或移交

更新 `project/tasks.json` 的真实状态和证据引用，重新生成展示文件。按 `templates/HANDOFF.md` 写入 `worklogs/<task_id>-<agent>.md`，注明对应状态版本及下一步精确入口。

最后只据实说明：已验证完成的内容与证据、已实现但未验证的内容、真实失败/阻塞、下一项动作。已有授权范围内还能继续时继续，不为每个小步骤停下来请求许可。
