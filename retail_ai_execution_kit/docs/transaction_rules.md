# 购买、取消、退款与金额规则（DATA-08）

- 版本：`transaction-rules-v1`，2026-11-10，claude-opus-5-5 起草并自审
- 适用数据：合成交易包（契约 `synthetic-transaction-v1`，USD，完全合成）
- 可执行定义：`src/retail_bi/data/transactions.py`（DuckDB SQL）。`contracts/metrics.json` 引用同一份 SQL，`reports/data/transaction_reconciliation.json` 是实际运行结果。本文与代码不一致时，以代码和对账结果为准并修正本文。
- 这些是项目在 D012 用户授权下自行确定的工程口径，不是教师规定。

## 1. 有效购买

**有效购买 = 已审批的订单**：`approved_ts` 非空。

| 情况 | 订单数（历史层） | 是否有效 | 理由 |
|---|---:|---|---|
| 已送达 delivered | 8,655 | 是 | 已审批、已履约 |
| 已发货 shipped | 179 | 是 | 已审批，货已交承运商 |
| 处理中 processing | 283 | 是 | 已审批（支付已通过），尚未发货 |
| 已取消 cancelled | 194 | 否 | 没有审批 |

- 实测“已审批”与“最终状态不是 cancelled”逐单完全一致（对账检查 `approval_rule_matches_non_cancelled_status_exactly`）。
- 选审批而不是最终状态的原因：审批时间在当时就能观察到，最终状态是数据期末才知道的。用审批定义，任何时点的指标和特征都不会用到未来信息。
- 处理中和已发货订单从 2024 年起就零星存在（不是只集中在截止前），属于生成器的期末状态。它们已经审批，计入有效购买；只算已送达的口径作为敏感性对照：商品金额占有效口径的 95.2%。

## 2. 时间归属与可观察性

- 购买的业务时间是 **下单时间 `purchase_ts`**。金额、订单数都按下单时间归属到日、周、月。
- 在任意时点 `as_of`，只计 `approved_ts < as_of` 的订单。下单到审批最长 24 小时（实测）。
- 历史层保留了源数据中截止后才发生的审批。截止时（2026-11-08）有 **4 单已下单但尚未审批**，金额 740.29 USD（含运费），截止时不计入有效购买。
- 标签窗 `[t, t+h)` 结束后再等 1 天，审批才落定，标签才算成熟。

## 3. 取消

- 取消订单不计入有效订单数和任何销售金额，单独报告“取消订单数”和“取消订单商品金额”。
- 数据没有取消发生时间。取消按 **下单时间** 归属，并在指标说明中写明。
- 只在完整历史期间使用取消指标。`as_of` 早于截止时，未审批的订单无法区分“待审批”和“将被取消”。
- 取消订单也有支付记录（194 单，30,498.81 USD），但没有退款记录。项目不推断退款，也不把这部分支付称为损失或退款。

## 4. 退款、退货、冲销

- 数据中没有退款表、退货记录、负金额或冲销行（DATA-06 实测负值 0）。
- 因此不提供“退款金额”“净销售额（扣退款）”等指标。如果以后的数据出现负金额或冲销行，清洗阶段按规则进入隔离区，不在汇总里静默抵消。

## 5. 金额

| 名称 | 定义 | 允许的叫法 | 不允许的叫法 |
|---|---|---|---|
| 商品金额 | 有效订单明细 `item_price_usd` 之和 | 商品金额、商品销售额（模拟） | 已支付 GMV、净收入、利润、毛利 |
| 运费 | 有效订单明细运费之和 | 运费 | 收入 |
| 订单金额 | 商品金额＋运费；与支付记录逐单相等 | 订单金额（含运费） | 已支付金额 |
| 客单价 | 商品金额 / 有效订单数 | 每单商品金额 | — |
| 支付金额 | `payment_value_usd` | 只用于对账 | 收入、GMV |

- 金额全部用精确小数计算（契约类型 decimal(12,2)，DuckDB DECIMAL）。
- 没有数量列。不提供件数、单价×数量、销量类指标，`order_item_seq` 不是数量。
- 订单数一律按 `order_id` 去重，不按明细行计数。

## 6. 客户身份

- 客户级指标（购买客户数、RFM、复购）只使用已知 `customer_id` 的订单。本数据 `customer_id` 全部已知，未知客户 0 单。
- 经营汇总（订单数、金额）不要求客户身份。这条规则保留，以便数据变化时生效。

## 7. 隔离

- 类型解析失败、主键重复、外键孤儿：DATA-07 写入 `data/quarantine/`，本数据 0 行。
- 负金额、冲销行、无法关联原单的退款：本规则下全部进入隔离区，并在对账中单列。本数据 0 行。

## 8. 原始与有效的差额（实测，`reports/data/transaction_reconciliation.json`）

| 项 | 订单 | 明细行 | 商品金额 | 运费 | 订单金额 |
|---|---:|---:|---:|---:|---:|
| 原始（截止前下单的全部订单） | 9,311 | 15,639 | 1,408,601.73 | 132,257.78 | 1,540,859.51 |
| 减：已取消 | 194 | 319 | 27,778.26 | 2,720.55 | 30,498.81 |
| 减：截止时尚未审批 | 4 | 9 | 662.24 | 78.05 | 740.29 |
| **有效（截止时）** | **9,113** | **15,311** | **1,380,161.23** | **129,459.18** | **1,509,620.41** |

- 差额逐项等于取消与未审批两部分之和，没有其他原因（检查 `raw_minus_valid_equals_cancelled_plus_pending`）。
- 支付合计 1,540,859.51 等于原始订单金额；有效订单的支付合计等于有效订单金额。
