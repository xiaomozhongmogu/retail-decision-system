# 查询助手支持的问题与解析规则（AI-04）

- 版本 v1，2026-11-11，claude-opus-5-5；代码 `src/retail_bi/ai/query_intent.py`，检查 `evidence/AI-04/check_intent.py`
- 数据：只读发布的允许视图（完全合成数据，as_of 2026-11-08，不含）。问题先变成结构化意图，再由程序构造查询计划；**不让模型写 SQL**。

## 1. 支持的问题类别

| # | 类别 | 示例 | 视图 |
|---:|---|---|---|
| 1 | 某期商品金额 | 2026年10月的商品金额是多少？ | `ads.kpi_monthly` |
| 2 | 某期订单数 | 上个月有多少单？ | `ads.kpi_monthly` |
| 3 | 某期客单价（由合计重算） | 2025年的客单价是多少 | `ads.kpi_monthly` |
| 4 | 单月购买客户数（月内去重） | 2026年10月购买客户有多少？ | `ads.kpi_monthly` |
| 5 | 运费 | 2025年第四季度的运费一共多少 | `ads.kpi_monthly` |
| 6 | 取消订单 | 2025年取消了多少订单 | `ads.kpi_monthly` |
| 7 | 月度趋势 | 最近6个月商品金额的趋势 | `ads.kpi_monthly` |
| 8 | 按天趋势（最近一个审批落定的完整周） | 最近一周每天的销售额 | `ads.kpi_daily` |

## 2. 时间语义

“2026年10月”“2025年第四季度/2025年Q4”“2025年”“最近 N 个月”（以 2026-10 为最后一个完整月）、“上个月”=2026-10、“本月”=2026-11（不完整，附提示）、“上周/最近一周”=2026-10-31 至 2026-11-06（截止前最后一天审批未落定，不计入）、“今年”=2026（不完整）、“去年”=2025。2024-01 之前或 2026-11-08 之后返回“没有数据”。

## 3. 澄清与不支持

- 澄清：没有时间范围；“收入/业绩/GMV”（商品金额还是含运费）；“卖得最好”（按金额还是件数）；排名或占比没有维度；“对比”没说同比还是环比；识别不出指标。
- 不支持：毛利与利润、退款退货、渠道与投放、库存、年龄性别、浏览转化、州/城市/邮编、卖家、评价；按品类或大区的订单数、客户数、客单价（允许视图只有金额与明细行）；跨月去重客户数（月内去重不能相加）。

## 4. 枚举与校验

品类 16 个、客户大区 4 个，与发布版本中的取值一致（检查脚本核对）；中文别名（电子、手机、西部、中西部等）映射到英文值。所有意图都经过 `validate_intent()` 的目录校验：指标、维度、筛选值、问题类型、时间范围。

## 5. 模型的使用与额外校验路径

- 默认路径：规则解析 → 目录校验 → 可信查询计划（`plan()` 只产生 `runtime.query_view` 调用：视图、列、等值条件，加上月份范围、分组、求和与客单价重算），没有由问题拼出的 SQL 文本。
- 规则识别不出指标时，才把问题交给 LLM 填写同一份意图 JSON；结果必须通过同一个 `validate_intent()`，不通过就转为澄清，不会执行。
- 本版本不开启模型生成 SQL。若以后开启，模型生成的 SQL 只能交给 AI-05 的受限执行器（只读、只允许登记视图、单条 SELECT、行数上限），并与可信计划的结果对照后才能使用。
