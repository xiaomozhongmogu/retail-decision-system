# 项目验收标准

本文件规定如何证明完成，不表示测试已经执行。依据为《智能决策综合实践》2026指导书、选题报告模板及本项目范围约定。验收记录必须使用实际结果，失败、未运行和待教师确认均须保留。

## 一、要求等级与范围

| 标记 | 含义 | 适用范围 |
| --- | --- | --- |
| C | 课程来源要求与评分依据 | 具体区分teacher_required、teacher_framework、teacher_rubric与teacher_ambiguous，见需求JSON；不能都当无歧义硬要求 |
| U | 用户与本项目承诺 | 分层数仓与星型、RFM与复购、Streamlit、三个AI模块 |
| Q | 项目质量约定 | 对账、幂等、时间泄漏、AI测例、版本与复现；数值目标不是教师原文 |
| B | 可选加分 | 生产强化、微调、产品Demo、公开发表/竞赛、博客视频 |
| X | 可选分析扩展 | 销量预测、关联规则；未启用时不阻断核心验收 |

本矩阵使用与project/requirements.json一致的C/U/Q/B/X体系；C06、C16及部分加分解释保留未决状态。

课程数据门槛是“不少于10,000条记录**或**10MB”，同时不少于8个字段并含时间维度。数仓在指导书中为可选，本组因用户要求纳入U。算法列表是按业务选择的菜单，不能把销量预测和关联分析写成逐项必做；没有教师规定的AUC、F1通过线。正式承诺的扩展须先更新任务与范围，再纳入相应关卡。

时效条文“2026年1月以后”与另一处天池“2025年6月以后”需要解释。UCI Online Retail II、Cosmetics均为历史数据候选，须保留教师认可的时效口径或例外；2026重新上传不证明交易发生于2026。T-ECD已检查的单日零售分片仅6列且无金额，不能据此宣布整套满足8字段或交易建模要求。当前元数据调研不等于全量下载、清洗及数据验收。本文“全量”指已冻结且满足规模与时窗要求的正式研究范围；允许按用户保留完整历史的规范抽样，不要求下载发布者所有无关文件。

## 二、任务、结果与证据

`project/tasks.json`是唯一任务状态来源，使用GOV/DATA/DW/EDA/ML/AI/UI/DOC/REL/BON前缀。以下矩阵按前缀归类，不另建任务清单；每个用例映射到其中真实的`task_id`。

每个`done`任务必须有`evidence/<task_id>/`，至少保存：验收用例与预期、输入版本或夹具哈希、代码提交号（无Git时记录相关文件哈希）、实际命令或操作步骤、执行时间、原始结果及审阅结论；模型、规则、提示词、知识库版本按需补齐。截图辅助解释，不能替代数值结果与运行日志。建议统一保存`cases.csv`、`results.json`和`run.log`，敏感数据留在受控位置并记录索引。

用例结果使用`not_run / passed / failed / blocked / not_applicable`；不适用须说明原因。未执行、只有代码生成、只有截图样稿、仅有厂商宣传指标均不能判通过。必需用例失败或阻塞时，任务不能`done`。自动脚本只能检查证据存在、结构与可机械核对的断言，不能独立证明业务口径正确或教师已认可。

## 四、传统模型矩阵

以下90天/30天、发票频次和金额定义是交易主路线默认标准。正式切换行为路线时，DATA-03、ML-01须同步修改契约、相关任务验收和页面标题，再按冻结后的定义验收；不能在无订单或金额时硬套RFM。

| 域／等级 | 失败案例与通过条件 | 证据 |
| --- | --- | --- |
| ML／U+Q | F按明细计数、负M直接取对数、聚类编号当生命周期：黄金样本验证R/F/M；F按有效发票；生命周期规则、分群、风险分别解释 | 手算对照、特征表、群画像；k与种子比较 |
| ML／U+Q | as_of边界错位、观察不足仍标未复购：特征窗`[t−90天,t)`，标签窗`[t,t+30天)`；未来有合格购买为1；标签须成熟 | 窗口边界夹具、标签清单、剔除计数 |
| ML／U+Q | 随机拆交易行、全量拟合预处理、未来退款泄漏：按as_of时间划分，标签在下一评估期前成熟；用于预测的变换、选特征和聚类仅拟合训练期 | split manifest、特征血缘、模型流水线与断言 |
| ML／U+Q | 训练母体外硬给概率：近期90天有有效购买的已知客户为核心母体；长期沉睡客户进规则队列；缺字段有明确处理 | 覆盖统计、边界客户用例、服务返回 |
| ML／U+Q | 两个模型给矛盾风险、单类测试仍报AUC：风险定义为`1−P(未来30天复购)`，明确只是该窗口不复购；空/单类不伪造指标 | 正类定义、逐样本标签预测、独立指标复算 |
| ML／U+Q | 用测试集调参、只报最好结果：同划分比较规则、Logistic与LightGBM；阈值/校准在验证集冻结，测试集最终评估 | ROC/PR-AUC、KS、F1、Recall@K、Lift@K、Brier及样本量、正类率 |
| ML／Q | 重复客户快照当独立样本、预测当营销增益：披露客户数与快照数，区间估计考虑客户/时间依赖；不宣称因果提升或真实ROI | 评估说明、模型卡、基线选择理由 |
| BON／X | 若承诺销量预测，随机拆时间或无朴素基线；若承诺关联规则，购物篮混乱 | 预测滚动回测与朴素基线、MAE/WAPE；关联的篮子定义、支持度/置信度/提升度与留出验证 |

模型低于简单基线须如实报告并选择合理方案，不能为“通过”编造分数。技术流程正确与业务预测价值分别评价。

## 五、三个AI模块与公共RAG

以下测例规模和目标均为Q，需在调试前冻结题库、支持范围、评分方式与版本。人工或黄金结果复核优先，不能只用另一个LLM判卷。

| 范围 | 必测失败案例与通过标准 | 证据 |
| --- | --- | --- |
| NL2SQL | 至少40题，其中至少24题在声明支持范围内可回答；这些题的结果正确率≥90%。单独统计歧义澄清和拒绝；已声明拒绝测例全部拦截 | 问题、黄金结果、意图/SQL、实际结果、分类分母、逐题评分 |
| 查询后端 | 直接绕过UI提交写操作、未授权表、外部文件/网络读取、ATTACH/COPY/扩展、无限结果请求：可信构造器或严格校验、白名单、资源限制确实生效 | 后端测试及审计日志；AGENTS/Prompt不能替代权限控制 |
| 公共RAG | 至少20例覆盖正确命中、无依据、旧规则、冲突文件、检索内容夹带指令；有依据才回答，证据版本可追踪，冲突明确提示 | 检索片段、版本、引用、人工评审结果 |
| 经营周报 | 至少20例覆盖分母0、环比负数、缺失期、单位错误、未成熟数据与错误引用。所有数值和比较绑定结构化证据；模板注入数字；原因推测不写成事实 | SQL→证据JSON→报告链路、数值/单位/期间/引用校验、修复或降级记录 |
| 营销Agent | 至少30例，覆盖母体外客户、无适用优惠、超预算、重复触达、无触达同意、政策冲突、工具失败重试。代码校验约束，文案不可突破；只生成可审阅草稿 | 状态与工具调用、规则命中、预算校验、幂等草稿ID、逐例结果 |
| 真实集成 | 三模块各有独立输入输出、实际LLM调用与失败降级证据；模拟政策和触达历史明确标注；回放只证明演示可展示，不能冒充当前在线成功 | 请求ID、模型/Prompt版本、脱敏响应、成本/异常日志与模式标识 |

Agent使用风险排序并不证明优惠能挽回客户。没有随机实验或可靠处理结果，不验收“提高销售额”等真实效果承诺。

## 七、阶段关卡

| gate | 截止与放行条件 |
| --- | --- |
| `proposal-ready` | 2026-11-09：数据证据满足较严格时间条款，或时效解释/例外已获教师确认，实际数据可读且有初步预处理证据；业务、技术、范围和分工冻结；选题报告完整、参考文献>10。仅元数据核验不得放行 |
| `midterm-ready` | 2026-11-30：分层数仓、关键对账、OLAP、RFM与复购模型完成，评估能重跑；中期报告与演示通过。不得以虚构模型成绩补缺 |
| `final-ready` | 2026-12-22前：三个AI模块、UI、独立环境复现、正式材料与个人贡献证据完成；核心失败项关闭，扩展完成或明确未承诺；打包版本冻结 |
| `final-submitted` | 在`final-ready`基础上，实际提交到指定位置并保存凭证、时间和包哈希。材料就绪、待上传或提交失败均不能替代此状态 |

每次关卡保留审阅人、日期、必需任务结果、未决项和证据索引。教师未决口径属于`blocked`，不通过改写规则、改文件名或补一张“通过”截图绕过。

业务任务验收摘要统一使用templates/EVIDENCE.json结构。任务条件须全部passed；更细的测试用例可记录not_applicable及理由，但不能用它替代任务级必需条件。active任务的owner与done任务的实际reviewer必须记录，单代理自审如实标self_review。

依赖说明：depends_on约束最终done验收；基于稳定契约的离线先行可以开展，但要标明未集成或待真实调用，不能提前done。每阶段提交/答辩发生时立即留回执，REL-07只是终期汇总，不是前两阶段交付的前置。
