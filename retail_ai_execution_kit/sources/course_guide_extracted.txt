(二) 数据预处理
对采集到的大数据集合进行预处理,以保证大数据分析与预测结果的准确性与价值性,一般包括以下几个步骤:
1. 数据清理
缺失值处理:删除、均值/中位数/众数填充、KNN 填充、多重插补、模型预测填充。
异常值检测:3σ 准则、IQR 箱线图法、孤立森林(Isolation Forest)、DBSCAN 聚类、One-Class SVM。
噪声数据处理:分箱(等宽/等频)、回归平滑、聚类去噪。
重复数据去重:精确匹配去重、模糊匹配去重(如基于 Levenshtein 距离)。
2. 数据集成
将多个数据源的数据进行集成,形成集中、统一的数据库、数据立方体等。技术要点:
实体识别与匹配:主键匹配、模糊匹配、机器学习匹配(如 Magellan、DeepER)。
数据冲突解决:投票法、加权平均、置信度排序、人工审核。
数据冗余处理:相关性分析(皮尔逊系数、卡方检验)、PCA 降维。
3. 数据归约
在不损害分析结果准确性的前提下降低数据集规模:
维度归约:PCA、t-SNE、UMAP、LDA、自编码器(Autoencoder)。
数据量归约:随机抽样、分层抽样、聚类抽样、Reservoir Sampling。
数据立方体聚集:按时间、空间、类别维度进行聚集汇总。
4. 数据转换
通过转换实现数据统一:
标准化/归一化:Z-Score 标准化、Min-Max 归一化、Robust Scaler、Log 变换。
离散化:等宽分箱、等频分箱、决策树分箱、卡方分箱(ChiMerge)。
编码转换:One-Hot Encoding、Label Encoding、Target Encoding、Embedding 编码。
特征构造:时间窗口特征、滑动统计特征、交叉特征、自动特征工程(FeatureTools)。

(三) 数据处理
数据的类型和存储形式决定了其所采用的数据处理系统,而数据处理系统的性能与优劣直接影响大数据质量的价值性、可用性、时效性和准确性。
1. 数据存储架构选择
架构类型 | 代表技术 | 适用场景
关系型数据库 | MySQL、PostgreSQL、Oracle | 结构化数据、事务处理
数据仓库 | Hive、ClickHouse、Snowflake、Doris | OLAP 分析、报表查询
数据湖 | HDFS、Amazon S3、阿里 OSS、MinIO | 海量异构数据存储
湖仓一体 | Apache Iceberg、Delta Lake、Hudi、Paimon | 新一代统一架构(2026 主流)
向量数据库 | Milvus、ChromaDB、Qdrant、Pinecone | RAG/语义检索(AI 必备)
图数据库 | Neo4j、JanusGraph、NebulaGraph | 知识图谱、关系网络

2. 数据仓库建模（可选）
包括数据仓库的物理模型、概念模型及逻辑模型的设计及分析。常用建模方法:
维度建模(Kimball):星型模型(Star Schema)、雪花模型(Snowflake Schema)、星座模型(Galaxy Schema)。
范式建模(Inmon):3NF 范式、企业级数据仓库(EDW)。
Data Vault 2.0:Hub-Link-Satellite 三层结构,适合敏捷数仓建设。
OneData 体系:阿里巴巴的方法论,包含 ODS-CDM(DWD/DWS)-ADS 分层。
3. 多维分析(OLAP)（数据展示）
在多维数据集上进行如下操作:
切片(Slice):在某一维度上选定一个固定值。
切块(Dice):在多个维度上选定区间。
钻取(Drill Down/Up):从概要数据到细节数据,或反之。
旋转(Pivot):交换维度位置,变换视图。
(四) 数据分析
数据分析是大数据处理与应用的关键环节,它决定了大数据集合的价值性和可用性,以及分析预测结果的准确性。在数据分析环节,应根据大数据应用情境与决策需求,选择合适的数据分析技术。
1. 描述性分析
回答"发生了什么?"——统计指标(均值、方差、分位数)、频率分析、可视化探索性数据分析(EDA)。
2. 诊断性分析
回答"为什么发生?"——关联性分析(相关系数、卡方检验)、因果分析(Granger 因果、DoWhy)、根因分析(RCA)。
3. 预测性分析(传统机器学习)
任务类型 | 代表算法 | 应用场景
分类 | Logistic、SVM、随机森林、XGBoost、LightGBM、CatBoost | 客户流失预测、信用评分
回归 | 线性回归、岭回归、Lasso、ElasticNet、XGBoost | 销售额预测、价格预测
聚类 | K-Means、DBSCAN、HDBSCAN、层次聚类、Spectral Clustering | 用户分群、商品聚类
关联规则 | Apriori、FP-Growth、ECLAT | 购物篮分析、商品推荐
异常检测 | Isolation Forest、One-Class SVM、LOF、Autoencoder | 反欺诈、设备故障
时间序列 | ARIMA、SARIMA、Prophet、ETS、状态空间模型 | 销量预测、趋势预测

4. 预测性分析(深度学习)
前馈神经网络(MLP):适用于结构化数据的非线性建模。
卷积神经网络(CNN):图像识别、视觉商品分类、医疗影像分析。
循环神经网络(RNN/LSTM/GRU):时间序列预测、文本序列建模。
Transformer:新一代主流架构,包括 BERT、GPT 系列、时序模型 Informer/TimesNet/PatchTST。
图神经网络(GNN):GCN、GAT、GraphSAGE,用于社交网络、推荐系统、知识图谱。
表格深度学习:TabNet、TabTransformer、FT-Transformer,处理结构化数据。
自编码器(Autoencoder):特征降维、异常检测、数据生成。
5. 处方性分析(决策优化)
回答"应该怎么做?"——运筹优化(线性规划、整数规划)、强化学习(Q-Learning、DQN、PPO)、A/B 测试、因果推断。

2. 检索增强生成(RAG)系统构建
RAG(Retrieval-Augmented Generation)是 2026 年企业数据问答系统的主流方案。它将企业私域数据与 LLM 结合,既利用 LLM 的语言能力,又确保答案基于真实业务数据,解决了 LLM 的"幻觉"和"知识截止"问题。
(1) RAG 系统的核心组件
组件 | 技术选型 | 作用
文档加载 | LangChain Loaders、LlamaIndex Readers、Unstructured | 加载 PDF、Word、Excel、HTML、数据库等
文本切分 | RecursiveCharacterTextSplitter、Semantic Chunker | 将长文本切分为合适粒度的 chunks
嵌入模型 | BGE-M3、bge-large-zh-v1.5、text-embedding-3-large、Qwen-Embedding | 将文本转换为向量表示

# RAG 系统完整实现示例from langchain.document_loaders import DirectoryLoader, PyPDFLoaderfrom langchain.text_splitter import RecursiveCharacterTextSplitterfrom langchain.embeddings import HuggingFaceEmbeddingsfrom langchain.vectorstores import Chromafrom langchain.chains import RetrievalQAfrom langchain.llms import OpenAIfrom langchain.prompts import PromptTemplate # 1. 加载业务文档(可以是产品手册、销售数据说明、年报等)loader = DirectoryLoader('./company_docs/', glob="**/*.pdf", loader_cls=PyPDFLoader)documents = loader.load()print(f"加载了 {len(documents)} 份文档") # 2. 文本切分text_splitter = RecursiveCharacterTextSplitter(    chunk_size=500,    chunk_overlap=50,    separators=["\n\n", "\n", "。", "!", "?", ";"])chunks = text_splitter.split_documents(documents)print(f"切分为 {len(chunks)} 个块") # 3. 创建向量数据库(使用中文优化的 BGE 嵌入模型)embeddings = HuggingFaceEmbeddings(    model_name="BAAI/bge-large-zh-v1.5",    model_kwargs={'device': 'cuda'}  # 有 GPU 时使用)vectorstore = Chroma.from_documents(    documents=chunks,    embedding=embeddings,    persist_directory="./chroma_db") # 4. 构建检索 QA 链prompt_template = """请基于以下检索到的业务文档,回答用户的问题。如果文档中没有相关信息,请明确说明,不要编造答案。 参考文档:{context} 用户问题:{question} 回答:""" PROMPT = PromptTemplate(template=prompt_template, input_variables=["context", "question"]) qa_chain = RetrievalQA.from_chain_type(    llm=OpenAI(model="deepseek-chat", openai_api_base="https://api.deepseek.com/v1"),    chain_type="stuff",    retriever=vectorstore.as_retriever(search_kwargs={"k": 5}),    chain_type_kwargs={"prompt": PROMPT},    return_source_documents=True) # 5. 提问query = "2025 年公司毛利率较前一年是否有提升?主要原因是什么?"result = qa_chain({"query": query})print(f"答案:{result['result']}")print(f"参考来源:{[doc.metadata for doc in result['source_documents']]}")
(3) RAG 系统的进阶优化
混合检索(Hybrid Retrieval):结合向量检索(语义)+ BM25(关键词)的混合检索,提升召回率。
查询重写(Query Rewriting):用 LLM 改写用户问题,扩展同义词、补充上下文。
HyDE(假设性文档嵌入):先让 LLM 生成假设答案,再用假设答案做向量检索。
Self-RAG:让 LLM 自适应判断是否需要检索、检索结果是否相关。
GraphRAG(微软提出):构建知识图谱,在图上做多跳检索。
Agentic RAG:将 RAG 与 Agent 结合,实现复杂多步推理。
