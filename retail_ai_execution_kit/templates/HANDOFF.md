# 单任务交接模板

> 保存到 `worklogs/<task_id>-<agent>.md`。同一文件追加带时间的记录，不覆盖历史事实。本记录是某一时刻的快照；当前状态始终以 `project/tasks.json` 为准。

## 1. 快照与接手范围

- 实际记录时间：`<实际时间，不猜测>`
- 任务 ID / 本轮执行者：`<实际标识>`
- 角色：`<协调执行 / 局部实现 / 只读审查>`
- 对应任务台账版本或摘要：`<实际值>`
- 分支、提交或补丁基线：`<实际值；未使用 Git 时说明>`
- 有效规格/契约、数据和模型版本：`<本任务涉及的版本>`
- 所有权状态：`<仍持有 / 已由协调者释放 / 已明确移交；以台账为准>`

如果接手者读到的台账较新，先比对差异，不能用本快照覆盖新状态。

## 2. 本次实际完成的工作

| 实际修改或核验 | 文件/来源位置 | 对应要求或任务条件 | 证据位置 |
|---|---|---|---|
| `<已发生的动作>` | `<实际路径>` | `<ID 或条件>` | `<evidence/<task_id>/ 下文件>` |

只记录真实动作。生成了一份文件、应用了补丁、实际执行了程序是不同步骤，不合并描述为“全部完成”。只读审查写明没有修改实施文件。

## 3. 验证范围与真实结果

| 命令或核验步骤 | 是否实际执行 | 实际结果 | 未覆盖的范围 |
|---|---|---|---|
| `<实际命令/交互/来源核验>` | `<已执行 / 未执行 / 用户提供结果>` | `<退出状态、断言、观察结果>` | `<范围与限制>` |

- 已验证且适用于当前版本的内容：`<证据 ID 或路径>`
- 已实现但未运行/未验收的内容：`<具体项>`
- 模拟、样本、回放或真实 API 的使用情况：`<实际情况>`
- 与目标 Mac/ARM64 或其他环境尚未验证的差异：`<如适用>`

无执行能力不能写“运行成功”；用户转贴结果需标明来源，不能冒称亲自运行。失败结果保留，跳过项不计通过。

## 4. 尚未解决的事项

- 实际失败或阻塞及日志：`<问题、证据位置>`
- 已尝试的修复与结果：`<实际尝试，避免接手者重复>`
- 恢复条件：`<需要什么输入、环境或决定>`
- 仍待确认的教师口径或数据事实：`<未确认事项及相关记录>`
- 已有授权与有效决策：`<ops/DECISIONS.md 或用户指示依据；避免重复审批>`
- 不受该阻塞影响、可继续的工作：`<具体任务 ID>`

## 5. 防止覆盖与重复执行

- 未提交修改及归属：`<实际文件与所有者；未知则明确未知>`
- 仍在运行的进程/下载/训练/API 作业：`<实际标识和检查方式；无则据实写无>`
- 不应重复执行的步骤及原因：`<如昂贵训练、非幂等导入>`
- 需要协调者集成的补丁或共享接口变更：`<路径、基线与说明>`
- 已失效的旧证据及相关 `stale` 任务：`<仅列实际受影响项>`

## 6. 下一步精确入口

1. `<下一条具体动作、实际文件或已确认的命令>`
2. `<紧随其后的验收断言与证据保存位置>`
3. `<完成或仍阻塞后应更新的任务与交接>`

如确实需要新决定，列出具体差异、现有授权为何不足及推荐选项；已有授权覆盖的工作继续做。不要将交接变成强制逐步等待用户的审批。

## 7. 台账同步说明

- 本轮是否已由协调者更新唯一任务台账：`<实际情况>`
- 展示文件是否已通过 `scripts/project.py render` 重新生成：`<实际情况；未运行则写未运行>`
- 不一致或尚待集成的地方：`<如实列出>`

本记录不能单独把任务改成 `done`。完成状态必须由台账中的有效验收证据支撑。
