## 4. 已知差异（如实保留）

| 差异 | 原因 | 影响与处理 |
|---|---|---|
| 数据发布包检查中“工程导入层文件与登记一致”一项失败 | 导入层的 `manifest.json` 记录了归档文件的**绝对路径**，换目录重建后哈希不同；该层其余 11 个数据文件哈希相同，下游各层目录名一致 | 不影响数据。要消除这个差异，需要改为相对路径，并重新登记 DATA-05 至 DATA-12，本次没有改。`docs/data_readme.md` 中“另一路径重建 16 个文件一致”的说法，可能没有包含这个 manifest |
| 冻结记录中的发布名为 `wh-db316daf8021`，新机器构建出 `wh-d3aaa559048c` | 特征与训练是在加入评分表之前的发布上做的 | 交易数据与特征逐列相同；新机器上运行检查时保留本机生成的记录（手册第 4a 节） |
| 用 `fetchall()` 读取带时区的时间列会报 `pytz` 缺失 | 锁文件里没有 `pytz`，新旧环境相同 | 页面和 AI 能访问的视图里没有这类列；手册第 8 节已写明 |

## 5. 跨平台与展示机器

- **只验证了 macOS arm64（M1 Pro）。** 没有在 Windows、Intel Mac 或 Linux 上运行，不能声称这些平台可用。
- 已知的平台相关点：
  - LightGBM 在 macOS 上需要 `brew install libomp`。
  - 锁文件是按 `aarch64-apple-darwin` 生成的；其他平台需要重新生成，命令见 `docs/COMMANDS.md`。
  - Windows 上的路径和 shell 命令（`cp -R`、`.venv/bin/`）需要相应改写。
- 展示用电脑尚未确定。如果用这台 M1 Pro 演示，本报告就是对它的验证；换别的电脑，需要在那台电脑上按手册重做一次，并记录结果。
